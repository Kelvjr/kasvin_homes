# Airbnb calendar exchange (M2)

In Airbnb, open the listing calendar's availability settings, find calendar export, and copy that listing's private iCal URL. In the Kasvin admin API, create a calendar connection for the matching apartment using `POST /api/v1/admin/apartments/:id/calendar-connections` with `{ "url": "https://..." }`. Keep the URL private; it is a bearer secret. The admin response and status list omit it.

Trigger `POST /api/v1/admin/apartments/:id/calendar-connections/:connectionId/sync` to import immediately. The importer accepts complete `VCALENDAR` feeds, all-day and timezone-resolved date-time VEVENTs, folded lines, duplicate identical UIDs, updates, removals, and cancellation. Recurring or floating-time events fail the entire import rather than risk under-blocking dates. No imported event is deleted until fetch, parse, and validation all succeed. A failed import retains prior events and marks the connection failed. The database lease prevents simultaneous syncs for one connection. Only enabled connections run.

Run `pnpm --filter @kasvin/api sync:calendars` for all enabled feeds, or append a connection UUID for one. It is independently invokable by a future Railway cron job; no scheduler has been deployed. A production scheduler could run every 30–60 minutes with `DATABASE_URL` configured. Feed refresh by Airbnb and Kasvin is not immediate, so direct booking should always treat the current status as advisory. Status lists expose last attempt, last success, last error, sanitized error code, event count, and freshness. Set `freshnessMinutes` per apartment; default is 240. If `requireExternalSync` is true, missing, failed, never-synced, or stale feeds make the apartment unverified and unavailable for a public quote. Investigate the status/error code, correct or replace the URL, then sync again. No guest names or calendar descriptions are retained.

Fetcher security: HTTPS hostnames only, no IP literals or local names, all DNS answers must be public IPv4 or IPv6 addresses, the chosen address is pinned for TLS connection, each redirect is revalidated (maximum three), 10-second socket timeout, 15-second total deadline, 2 MB response limit, and a calendar-compatible content type. Failures expose only a sanitized code. Recurrence requires a future bounded expansion policy before support can be enabled.

For export, use `POST /api/v1/admin/apartments/:id/export-token`. The returned token and path are shown once. Resolve the path against the public API origin and add that URL to Airbnb's calendar import settings. Rotate by POST again or revoke by DELETE. The database stores only a SHA-256 hash of the token. The feed contains manual unavailable blocks with stable UIDs and exclusive end dates. It omits imported Airbnb events to avoid a sync loop and omits private notes. M3 confirmed reservations will need to be added to the export only after booking models exist. Protect the URL as a secret and avoid posting it publicly.
