# M2 — Availability, pricing, and calendar synchronization

## Scope and implementation

M2 adds date-based availability, manual blocks, configurable stay rules and pricing, nonbinding quotes, Airbnb iCalendar import, and a secret-token iCalendar export. It changes only the API and database packages plus documentation and the package lockfile. No booking, payment, guest account, frontend, or Flutter feature was added. M0/M1 endpoints and models remain in place.

The additive migration `20261119204446_m2_availability_pricing_calendars` creates `ManualAvailabilityBlock`, `CalendarConnection`, `ExternalCalendarEvent`, `NightlyRateOverride`, `ApartmentPricingSettings`, `WeekdayRate`, `LengthOfStayDiscount`, and `CalendarExportToken`, plus block/provider/sync enums. It adds foreign keys, interval and positive-value checks, uniqueness constraints, and indexes for overlap queries. The follow-up migration `20261120090000_cap_stay_discount_at_30_percent` enforces the configured 30% maximum. Neither migration changes or deletes M1 rows.

## Rules

- Civil dates use `Africa/Accra`, `YYYY-MM-DD`, and half-open `[checkIn, checkOut)` occupancy. Invalid and past stays fail validation. Search/calendar spans are capped at 366 nights; quotes at 90.
- Public availability requires a published apartment, capacity and stay-rule compliance, no overlapping manual/imported block, and a fresh successful external sync when that apartment requires one. The default is `requireExternalSync: true`; an admin must deliberately disable it if no feed is needed. A failed import retains old events and marks the feed unverified.
- Pricing chooses a date override, then weekday rate, then base rate. The highest eligible length threshold supplies one discount, rounded half-up once on the subtotal. Missing/invalid prices fail rather than silently becoming zero. Quotes are accommodation-only and nonbinding.
- Calendar import fetches over HTTPS with public DNS address validation and address pinning, redirect checks, time and size limits, full parse before transactional reconciliation, and per-connection database leases. Recurrence and ambiguous floating times are rejected fail-closed. The command `pnpm --filter @kasvin/api sync:calendars [connectionId]` can be scheduled later; no production cron job is deployed.
- Export uses a random token whose SHA-256 hash is stored in PostgreSQL. Rotation invalidates the prior token. The feed contains active manual blocks only, with stable UIDs and no notes or imported events.

See [availability API](../api/availability.md), [pricing API](../api/pricing.md), and [Airbnb calendar setup](../integrations/airbnb-calendar.md) for exact endpoints and operational steps.
