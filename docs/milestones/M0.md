# M0 — Development foundation

## Objectives

Create a reproducible pnpm and Turborepo workspace, independent website and dashboard, Express API, PostgreSQL and Prisma foundation, tests, CI, and documentation. Exclude all M1 business features.

## Implemented

- pnpm 11 workspace and lockfile, Turborepo 2 tasks, Node.js 24 LTS target
- Two independent Next.js 16 applications with static placeholder pages and distinct ports
- Express 5 API with validated configuration, explicit CORS origins, security headers, rate limiting, request logging, safe errors, graceful shutdown, health and readiness routes
- Prisma 7 PostgreSQL setup with an empty schema, generated client, adapter, reusable connection utility, and future migration scripts
- Shared TypeScript package, base TypeScript config, optional local PostgreSQL Compose file, example environment files, GitHub Actions CI, and documentation

## Executed checks

- `pnpm install --frozen-lockfile` — passed after explicitly allowing Prisma and esbuild install scripts.
- `pnpm --filter @kasvin/database generate` — passed with an empty schema.
- `pnpm build` — passed for API, database, shared package, website, and dashboard.
- `pnpm typecheck` — passed.
- `pnpm lint` — passed.
- `pnpm test` — six API tests passed. Supertest required localhost socket access outside the restricted sandbox.
- `pnpm format:check` — passed.
- `pnpm dev` — website, dashboard, and API served HTTP 200 on 3000, 3001, and 4000.
- Compiled API `/api/v1/ready` — HTTP 503 without PostgreSQL and HTTP 200 against temporary PostgreSQL 18.0.
- Built Next.js apps — each served its placeholder with HTTP 200.

## Issues and limits

The local machine has Node.js 26.13.0, while CI targets Node.js 24 LTS. The local checks passed on Node 26; GitHub Actions on Node 24 has not run because nothing was pushed. Docker is unavailable, so a temporary local PostgreSQL 18 instance was used for the smoke test instead of Compose. Next.js Turbopack failed to create a CSS worker inside this Windows sandbox, so the website and dashboard use the Webpack option. A later concurrent build hit an intermittent Windows `EPERM`; the root build now runs packages sequentially and passed. No production deployment or third-party service account was configured.

## Completion status

M0 implementation and local acceptance checks are complete. Remote CI remains unverified until a future push, which was not authorized as part of M0.
