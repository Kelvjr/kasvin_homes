# M1 — Database Schema & Apartment Management

## Objectives and scope

Store apartments, amenities, and image metadata; expose public reads and protected administrative management through the existing Express API. No frontend, booking, date availability, payments, or image upload work is included.

## Implemented

- `Apartment` with permanent UUID, immutable unique code, editable name and unique slug, optional details, integer base rate in pesewas, currency default `GHS`, publication status, and timestamps.
- `Amenity`, explicit `ApartmentAmenity` link, and ordered `ApartmentImage` metadata.
- Prisma migration `20261119114610_apartment_foundation` with foreign keys, uniqueness, numeric checks, publication completeness, and a partial unique index permitting one cover image per apartment.
- Idempotent Prisma 7 seed for SIRIUS, EMERALD, EOS, and APOLLO in `DRAFT`, with unknown prices, capacities, bathrooms, descriptions, amenities, and images unset.
- Public published-only list and detail routes; administrative apartment, amenity, and image routes; Zod validation, filtering, pagination, safe archiving, and safe error responses.
- Production admin routes fail closed pending Clerk. A random, explicitly configured `DEV_ADMIN_TOKEN` works only outside production for backend testing.

## Migration and seed commands

In `packages/database`, with `DATABASE_URL` targeting a disposable local development database:

```sh
pnpm --filter @kasvin/database exec prisma validate
pnpm --filter @kasvin/database migrate:dev
pnpm --filter @kasvin/database generate
pnpm --filter @kasvin/database seed
```

The migration was applied to a temporary PostgreSQL 18 development database using `migrate:dev` and independently to a fresh isolated test database using `migrate:deploy`. It was also applied to the user's previously empty local `kasvin_homes` development database at `localhost:5432`. The seed command ran twice against that database and produced exactly the four official drafts without duplicates. The integration suite confirmed repeat seeding preserves an edited name. No production database was touched. The temporary test server and databases were removed after validation; the user's local database remains running with four apartments.

## API endpoints

Public: `GET /api/v1/apartments`, `GET /api/v1/apartments/:slug`.

Administrative: `GET|POST /api/v1/admin/apartments`, `GET|PATCH|DELETE /api/v1/admin/apartments/:id`, `PATCH /api/v1/admin/apartments/:id/status`, `PUT /api/v1/admin/apartments/:id/amenities`, `POST /api/v1/admin/apartments/:id/images`, `PATCH|DELETE /api/v1/admin/apartments/:id/images/:imageId`, `GET|POST /api/v1/admin/amenities`, and `PATCH /api/v1/admin/amenities/:id`. The full request and response contract is in [apartments.md](../api/apartments.md).

## Known limitations

The four seeded apartments remain unpublished until the business supplies positive nightly rates and maximum guest capacities. No images or amenities are assigned by default. Admin access is disabled in production until a future Clerk integration; the development token is for local backend testing only. The PostgreSQL integration suite runs only when `M1_TEST_DATABASE_URL` points to a disposable local `*_test` database. CI runs the credential-free tests and skips that suite.

The database package has a package-level Turbo dependency so its `typecheck` waits for its `build`. This prevents concurrent Prisma client generation in the same output directory.
